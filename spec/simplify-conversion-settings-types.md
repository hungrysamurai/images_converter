# SPEC: Упрощение типизации настроек конвертации

## Problem Statement

Типизация проекта громоздкая и плохо помогает разработчику, особенно в части настроек конвертации:

- Активный выходной формат и его настройки хранятся раздельно и никак не связаны в типах. Селектор настроек активного формата возвращает объединение всех вариантов настроек, поэтому в компонентах, энкодерах и агрегаторах приходится писать тайпгарды, которые проверяют наличие поля, хотя формат и так известен. В редьюсере сброса используется явный небезопасный каст.
- Для обновления стора существует набор «одноключевых» типов (по одному на каждую настройку) и их объединений. Компоненты-инпуты собирают payload вида «динамический ключ → значение» с кастом, а редьюсеры разбирают его обратно через извлечение первого ключа, тоже с кастом.
- Несколько TS-enum'ов дублируют одни и те же строковые значения форматов (входные форматы, выходные форматы, форматы с превью, типы компрессии PDF). Из-за номинальной природы enum'ов появляется перекрёстная индексация: выходные настройки индексируются входным enum'ом, и наоборот.
- Почти все типы объявлены через глобальное пространство имён, поэтому непонятно, откуда тип берётся. При этом enum'ы импортируются явно, и в одном файле смешаны два стиля.
- Состояние «выключено» у сглаживания и дизеринга в сторе кодируется как `false`, а в UI — как строка `off`. Из-за этого в компонентах и редьюсерах есть взаимные преобразования.
- Качество хранится в единицах сторонних библиотек: дробь 0–1 для JPEG/WEBP/PDF и инвертированная шкала 1–20 для GIF. Ради отображения существуют режимы конвертации слайдера, утилита конвертации и проп режима у слайдера.
- Enum единиц измерения смешивает значение настройки (пиксели/проценты) с чисто визуальными подписями (ppi, градусы, мс), поэтому тип настройки допускает бессмысленные значения.
- Задача для воркера описана дважды, почти одинаково. Конвертер принимает пять аргументов, один из которых выводится из другого.
- Настройки конвертации персистятся дважды: через собственный persist-конфиг и через корневой.

## Solution

Перестроить типы вокруг одного источника правды — карты «выходной формат → его настройки». Из неё выводятся все остальные типы, а селектор отдаёт дискриминированный union «формат + настройки», который сужается обычным `switch` по формату. Стор хранит значения ровно в том виде, в каком их видит пользователь, а адаптация к сторонним библиотекам происходит только на границе, в энкодерах и утилитах ресайза. Инпуты становятся «глупыми» controlled-компонентами, а стор обновляется набором маленьких типизированных экшенов, по одному на настройку. Глобальные типы заменяются модульными экспортами, разложенными по смыслу. Сохранённое у пользователей старое состояние один раз сбрасывается.

Поведение приложения для конечного пользователя не меняется, за исключением одного сброса сохранённых настроек при первом запуске новой версии. Заодно исправляется неверный MIME-тип при склейке в PDF.

## User Stories

1. As a разработчик, I want чтобы настройки активного формата сужались по типу при проверке формата, so that мне не нужны тайпгарды на наличие полей.
2. As a разработчик, I want один источник правды для списка выходных форматов, so that добавление формата требует правки в одном месте, а компилятор подсказывает все недостающие места.
3. As a разработчик, I want чтобы начальное состояние проверялось на полноту по всем выходным форматам, so that я не могу забыть настройки для нового формата.
4. As a разработчик, I want чтобы входные форматы выражались через выходные плюс дополнительные (HEIC, SVG), so that между ними нет дублирования и перекрёстной индексации.
5. As a разработчик, I want чтобы форматы с превью выводились из входных форматов, so that список не расходится с реальностью.
6. As a разработчик, I want получать MIME-тип по имени формата из одного объекта, so that мне не нужно собирать строку MIME шаблоном с кастом.
7. As a пользователь, I want чтобы склеенный PDF-файл имел корректный MIME-тип, so that скачивание и превью работают правильно.
8. As a разработчик, I want чтобы опции селектов (сглаживание, дизеринг, компрессия PDF, единицы ресайза) были `as const`-массивами с выведенными union-типами, so that один и тот же массив рендерится в `<select>` и задаёт тип.
9. As a разработчик, I want чтобы «выключено» у сглаживания и дизеринга хранилось как `off`, так же, как в UI, so that между стором и компонентами нет преобразований.
10. As a разработчик, I want чтобы преобразование `off` в формат Canvas API и gif.js происходило только в утилите ресайза, SVG-декодере, GIF-энкодере и GIF-агрегаторе, so that знание о библиотеках локализовано.
11. As a разработчик, I want чтобы после проверки на `off` значение сглаживания сужалось до типа качества сглаживания Canvas, so that каст больше не нужен.
12. As a разработчик, I want чтобы качество JPEG/WEBP/PDF хранилось в шкале 1–100, so that стор совпадает с тем, что видит пользователь.
13. As a разработчик, I want чтобы качество GIF хранилось в шкале 1–20, где больше значит лучше, so that шкала интуитивна и совпадает с отображением.
14. As a разработчик, I want чтобы перевод качества в единицы библиотек происходил только в энкодерах и GIF-агрегаторе, so that слайдер не знает о форматах.
15. As a разработчик, I want удалить режимы конвертации слайдера и утилиту конвертации значений, so that в проекте меньше кода.
16. As a разработчик, I want чтобы у каждой настройки был свой экшен с точным типом payload, so that в редьюсерах нет извлечения ключей и кастов.
17. As a разработчик, I want чтобы экшен смены единиц ресайза сам сбрасывал целевые ширину и высоту, so that это правило живёт в одном месте, как и сейчас.
18. As a разработчик, I want чтобы экшен задержки анимации сохранял текущее поведение (пустое значение превращается в значение по умолчанию), so that поведение UI не меняется.
19. As a разработчик, I want чтобы формат-специфичные экшены (качество, дизеринг, компрессия, merge, задержка анимации) молча игнорировались для форматов без такой настройки, so that редьюсеры безопасны и без кастов.
20. As a разработчик, I want чтобы инпуты (чекбокс, селект, число, слайдер) были controlled-компонентами со значением и колбэком `onChange` и не знали о сторе, so that их легко переиспользовать и типизировать.
21. As a разработчик, I want чтобы селект был дженериком по типу опции, so that колбэк получает значение точного union-типа, а не строку.
22. As a разработчик, I want чтобы числовые границы и шаг у числового поля и слайдера были числами, so that не нужны преобразования строк и проверки на null.

24. As a разработчик, I want чтобы единицы ресайза были union'ом только из пикселей и процентов, so that тип настройки не допускает бессмысленных значений.

26. As a разработчик, I want плоскую форму состояния настроек (активный формат, выходные настройки по форматам, входные настройки), so that пути доступа короче, а в редьюсерах не нужны глубокие деструктуризации.

## Implementation Decisions

**Модель выходных настроек**
- Вводятся базовые настройки ресайза: флаг ресайза, единицы, целевая ширина и высота (могут отсутствовать), сглаживание.
- Карта выходных настроек задаёт тип настроек для каждого формата:
  - JPEG, WEBP: ресайз + качество;
  - PNG, BMP, TIFF: только ресайз;
  - GIF: ресайз + качество + дизеринг + склейка + задержка анимации;
  - PDF: ресайз + качество + компрессия + склейка.
- Тип выходного формата выводится из константного массива форматов. Карта настроек должна покрывать ровно эти форматы, и начальное состояние проверяется на полноту через `satisfies`.
- Выходная цель — дискриминированный union «формат + настройки этого формата», выведенный из карты через mapped type.

**Форматы и опции**
- Константный массив выходных форматов в текущем порядке: jpeg, png, webp, pdf, bmp, gif, tiff. Он используется для типа, для циклического переключения и для списка выбора формата.
- Входной формат — это выходной плюс heic и svg. Формат с превью — входной без tiff и heic.
- MIME задаётся константным объектом с ключами по входному формату; из него выводится тип MIME.
- Сглаживание: off, low, medium, high. Дизеринг: off плюс все варианты gif.js (включая serpentine). Компрессия PDF: jpeg, png. Единицы ресайза: pixels, percentages. Все четыре задаются константными массивами с выведенными union'ами.
- Enum'ы языка, ориентации экрана и цветового режима остаются. Enum единиц, режимов конвертации слайдера, входных и выходных форматов, форматов с превью, сглаживания, дизеринга, компрессии и MIME удаляются.

**Значения в сторе и граница с библиотеками**
- «Выключено» у сглаживания и дизеринга хранится как off.
- Утилита ресайза и SVG-декодер включают сглаживание, только если оно не off, и тогда передают его как качество сглаживания Canvas.
- GIF-энкодер и GIF-агрегатор передают в gif.js `false` при off и само значение в остальных случаях.
- Качество: 1–100 для JPEG/WEBP/PDF (по умолчанию 75), 1–20 для GIF, где больше значит лучше (по умолчанию 10, что соответствует текущему 11). Энкодеры JPEG/PNG/WEBP и PDF делят на 100. GIF-энкодер и GIF-агрегатор передают в gif.js значение `21 − quality`.
- Остальные значения по умолчанию не меняются.

**Форма состояния слайса настроек**
- Три поля: активный формат, выходные настройки (карта по формату) и входные настройки (объект с ключом pdf, внутри разрешение и поворот).
- Внутренний хелпер возвращает настройки активного формата из draft-состояния.

**Экшены**
- Выбор формата: циклическое переключение; явный выбор по выходному формату; сброс настроек активного формата вместе с входными настройками PDF через дженерик-хелпер без кастов.
- Общие настройки ресайза: флаг ресайза, единицы (сбрасывают ширину и высоту), ширина, высота, сглаживание.
- Формат-специфичные: качество, дизеринг, компрессия, склейка, задержка анимации (пустое значение превращается в 200). Применяются, только если у настроек активного формата есть соответствующее поле; иначе ничего не делают.
- Входные настройки PDF: разрешение, поворот.
- Редьюсеры читают draft напрямую, без снимка.

**Селекторы**
- Активный формат.
- Активная выходная цель («формат + настройки»).
- Плоские входные настройки PDF.
- Отдельный селектор списка форматов не нужен: используется константа.

**Компоненты**
- Инпуты чекбокса, селекта, числа и слайдера становятся controlled-компонентами со значением и колбэком `onChange` и больше не вызывают dispatch.
- Селект — дженерик по строковому union'у опций.
- У числового поля и слайдера числовые min, max и step. Числовое поле принимает строковый суффикс-подпись. Слайдер больше не принимает режим формата.
- Панель выходных настроек получает выходную цель и рендерит формат-специфичный блок через `switch` по формату, передавая в инпуты колбэки с dispatch соответствующих экшенов.
- Панель входных настроек передаёт колбэки экшенов разрешения и поворота.

**Конвертер и воркер**
- Единый тип задачи: MIME-тип, blob URL, выходная цель, опциональные входные настройки PDF, опциональный bitmap. Тип результата — blob или массив blob'ов. Оба типа экспортируются из модуля рядом с воркером и используются и в пуле воркеров, и в конвертере.
- Конструктор конвертера принимает выходную цель, плоские входные настройки PDF и dispatch. Флаг склейки вычисляется внутри по наличию и значению поля склейки в настройках.
- MIME результата берётся из объекта MIME по выходному формату.
- Декодеры (single-page и multi-page), SVG-растеризатор, функция кодирования canvas и GIF-агрегатор принимают выходную цель. PDF-декодер дополнительно принимает плоские входные настройки PDF.
- Функция кодирования canvas сужает настройки через `switch` по формату и передаёт энкодерам уже суженные настройки.
- В воркере сохраняются рантайм-ошибки при отсутствии входных настроек PDF для PDF и bitmap для SVG.
- Место создания конвертера в слайсе обработки файлов использует новые селекторы и форму состояния.

**Раскладка типов**
- Глобальное объявление удаляется полностью, все типы экспортируются из модулей и импортируются явно.
- Общий модуль форматов: массив и тип выходных форматов, входные форматы, форматы с превью, проверка превью-формата, объект и тип MIME.
- Общий модуль файлов: исходный и обработанный файл.
- Модуль типов рядом со слайсом настроек: настройки ресайза, карта выходных настроек, выходная цель, входные настройки PDF, опции сглаживания, дизеринга, компрессии и единиц ресайза (массивы и типы), тип состояния слайса.
- Модуль рядом с воркером: задача конвертации и её результат.
- Общий модуль типов: только оставшиеся enum'ы.
- Файл тайпгардов удаляется. Проверка превью-формата переезжает в модуль форматов, проверка обработанного файла заменяется проверкой наличия ссылки на скачивание.

**Персистентность**
- Корневой persist-редьюсер удаляется, стор комбинирует слайсы напрямую.
- Persist-конфиг слайса настроек получает версию 1 и миграцию, которая для любой более старой версии возвращает пустое состояние, чтобы применилось начальное.
- Настройки redux-persist для игнорируемых экшенов в проверке сериализуемости сохраняются.

**Инструменты и порядок работ**
- Добавляется скрипт проверки типов без генерации файлов.
- Порядок коммитов (каждый должен проходить проверку типов и линтер):
  1. Форматы и опции на константных массивах и union'ах, объект MIME, удаление enum'а единиц, раскладка типов по модулям, отказ от глобального объявления.
  2. Новая форма состояния и карта настроек, off вместо false, новые шкалы качества, persist с версией и сбросом, удаление корневого persist.
  3. Гранулярные экшены, controlled-инпуты (колбэки, суффикс, числовые границы), панель выходных настроек на `switch` по формату.
  4. Выходная цель и единая задача в конвертере, воркере, декодерах и энкодерах; перевод шкал на границе; удаление тайпгардов, утилиты конвертации значений и режимов слайдера.
- Если шаги 1 и 2 невозможно разделить так, чтобы промежуточное состояние компилировалось, они объединяются в один коммит.

## Out of Scope

- Устранение дублирования почти одинаковых методов конвертации отдельных форматов в конвертере (у него есть свой TODO).
- i18n: тернарники по языку в компонентах остаются как есть.
- Стили и визуальные изменения UI.
- Перевод на union'ы enum'ов языка, ориентации экрана и цветового режима.
- Дискриминированный по MIME-типу тип задачи конвертации (сознательно выбраны опциональные поля с рантайм-проверками).
- Честная миграция старого persisted-состояния с пересчётом шкал (сознательно выбран сброс).
- Добавление автотестов.
- Изменения слайсов исходных и обработанных файлов сверх того, что требуется новыми типами.

## Further Notes

- В проекте нет автотестов, а сборка Vite не проверяет типы. Поэтому основная защита — новый скрипт проверки типов плюс линтер после каждого шага.
- Финальная ручная проверка в dev-режиме по каждому выходному формату:
  - изменение каждой доступной настройки;
  - конвертация одиночных и многостраничных файлов (TIFF, GIF, PDF, SVG, HEIC);
  - склейка в GIF и в PDF (включая корректный MIME склеенного PDF);
  - настройки растрирования PDF;
  - сброс настроек формата;
  - перезагрузка страницы: новые настройки сохраняются, а старое содержимое localStorage один раз сбрасывается без ошибок.
- Визуально качество GIF по умолчанию меняется с отображаемых 10 на те же 10. Внутреннее значение gif.js остаётся 11, так что фактическое поведение по умолчанию не меняется.
- Двойная запись настроек в localStorage (корневой ключ плюс собственный ключ слайса) после изменений пропадает. Старый корневой ключ может остаться в localStorage у существующих пользователей, но больше не читается.
