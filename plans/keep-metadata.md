# Plan: Сохранение метаданных (EXIF) при конвертации в JPEG

> Source SPEC: `spec/keep-metadata.md`

## Architectural decisions

Решения, общие для всех фаз:

- **Scope**: метаданные записываются только в JPEG. EXIF извлекается из JPEG, HEIC, AVIF, WebP и PNG. Остальные входные форматы EXIF не отдают, для них конвертация идёт как обычно.
- **Без сторонних библиотек**: собственный модуль EXIF из чистых функций над байтами. Он не парсит EXIF целиком, а переносит сырую TIFF-структуру и правит несколько тегов на месте.
- **Контракты модуля EXIF**:
  - экстрактор: байты исходного файла → сырые TIFF-байты EXIF или «нет EXIF»;
  - патчер: TIFF-байты + фактические ширина и высота результата → очищенные TIFF-байты. Некорректная структура даёт ошибку, а не мусор;
  - writer: закодированный JPEG + очищенные TIFF-байты → JPEG с APP1 `Exif\0\0` сразу после SOI. Если payload больше 65533 байт, writer отказывается писать.
- **Реестры форматов**:
  - запись реестра входных форматов получает опциональное lazy-поле экстрактора EXIF, по аналогии с `loadDecoder`;
  - запись реестра выходных форматов получает опциональное lazy-поле writer'а EXIF, по аналогии с `loadAggregator`;
  - хелпер «поддерживает ли цель метаданные» определяется по наличию writer'а и стоит рядом с `shouldMerge`. Его используют и UI, и пайплайн;
  - все импорты lazy, потому что реестры входят в бандл воркера.
- **Пайплайн**: сигнатуры декодеров и энкодеров не меняются. Метаданные обрабатываются отдельным шагом в общей функции пайплайна, поэтому воркер и main-thread fallback ведут себя одинаково. Шаг выполняется только при трёх условиях: настройка включена, у входного формата есть экстрактор, у выходного есть writer. Исходник повторно читается по blob URL. Патч применяется по размерам финального canvas, то есть после ресайза и фона. Любая ошибка даёт `console.warn` и файл без метаданных.
- **Модель настроек**: тип настроек JPEG отделяется от общего с WebP/AVIF и получает поле `keepMetadata: boolean` (по умолчанию `false`). Редьюсер `setKeepMetadata` ведёт себя как остальные format-specific редьюсеры: игнорируется, если у активного формата нет такого поля.
- **Persist**: reconciler мержит дефолты с сохранённым состоянием по ключам каждого формата. `CONVERSION_SETTINGS_VERSION` не поднимается. Версию нужно бампать только при переименовании или удалении полей и при смене их смысла.
- **Тесты**: vitest и скрипт `test`. Тестируется только модуль EXIF. Фикстуры синтетические и собираются программно, бинарников в репозитории нет.

## Phase 1: Переключатель «Keep metadata» с сохранением настроек

**User stories**: 1, 2, 3, 19, 20, 21, 22, 23, 24, 25, 30, 31 (выходная часть)

### What to build

У JPEG в панели выходных настроек появляется отдельная секция с переключателем «Keep metadata:» / «Сохр. метаданные» и значениями On/Off или Вкл/Выкл. Секция стоит между блоком настроек формата и блоком ресайза и отделена divider'ом. Она рендерится по хелперу поддержки метаданных, а не по switch по формату.

Состояние переключателя хранится в настройках JPEG, переживает перезагрузку и сбрасывается кнопкой Reset. Reconciler persisted-состояния переходит на поключевой мерж внутри формата, поэтому у пользователей, обновившихся со старой версии, сохраняются качество, ресайз и активный формат, а `keepMetadata` получает дефолт `false`. Комментарий о бампе версии в store обновляется.

В реестре выходных форматов объявляется поле writer'а EXIF. У JPEG оно временно заполнено writer'ом, который возвращает JPEG без изменений, а в фазе 2 заменяется настоящим. В пайплайне переключатель пока ни на что не влияет.

### Acceptance criteria

- [ ] Для JPEG виден переключатель в отдельной секции с divider'ами. Для остальных форматов секции нет.
- [ ] По умолчанию переключатель выключен, подписи в EN и RU соответствуют SPEC.
- [ ] Состояние переключателя сохраняется после перезагрузки страницы.
- [ ] Reset для JPEG выключает переключатель.
- [ ] Пользователь с persisted-настройками в старом формате, где нет `keepMetadata`, сохраняет свои значения качества, ресайза и активного формата и получает `keepMetadata: false`. Версия persist не поднята.
- [ ] `setKeepMetadata` ничего не делает, если активен формат без этого поля.
- [ ] typecheck и lint проходят.

## Phase 2: Tracer bullet — JPEG → JPEG с переносом EXIF и сбросом Orientation

**User stories**: 7, 10, 14, 15, 16, 18, 28, 29, 32, 33, 31 (входная часть)

### What to build

Первый сквозной путь: при включённом переключателе EXIF из исходного JPEG попадает в выходной JPEG.

Подключаются vitest и скрипт `test`. Появляются тестовые билдеры: TIFF-структура в `II` и `MM` с тегом Orientation и обёртка JPEG APP1. Модуль EXIF получает три части:

- экстрактор JPEG, который проходит по маркерам до APP1 `Exif\0\0`;
- патчер, который пока только выставляет Orientation в IFD0 в 1 (на месте, при обоих порядках байт);
- writer, который вставляет APP1 после SOI и отказывается писать при payload больше 65533 байт.

В реестре входных форматов у JPEG заполняется поле экстрактора, а заглушка writer'а из фазы 1 заменяется настоящим writer'ом. В общей функции пайплайна появляется шаг метаданных с условием «настройка + экстрактор + writer». При выключенной настройке исходник повторно не читается. Ошибки на любом этапе перехватываются, выдаётся `console.warn`, файл отдаётся без EXIF.

### Acceptance criteria

- [ ] `pnpm test` запускает vitest.
- [ ] Round-trip тест (извлечь → пропатчить → записать → извлечь) проходит для `II` и `MM`: Orientation = 1, остальные теги совпадают байт в байт.
- [ ] Граничные тесты: JPEG без EXIF даёт «нет EXIF», обрезанный или битый EXIF даёт ошибку патчера, EXIF больше лимита APP1 приводит к отказу writer'а.
- [ ] В браузере JPEG с EXIF Orientation = 6, сконвертированный в JPEG с включённым переключателем, отображается правильно, а в выходном файле есть EXIF с Orientation = 1.
- [ ] При выключенном переключателе выходной файл не содержит EXIF, повторного чтения исходника нет.
- [ ] Файлы без EXIF или с битым EXIF конвертируются без ошибки для пользователя, в консоли есть предупреждение.
- [ ] Цвета выхода с включённым и выключенным переключателем одинаковые: ICC-профиль не копируется.
- [ ] Метаданные сохраняются и при обработке в main-thread fallback.

## Phase 3: Корректные размеры и удаление миниатюры

**User stories**: 8, 9, 17

### What to build

Патчер получает остальные исправления.

- `PixelXDimension` и `PixelYDimension` в Exif IFD получают фактические размеры финального canvas, с учётом ресайза. Запись идёт на месте, по типу поля: SHORT или LONG.
- IFD1 удаляется: ссылка next-IFD у IFD0 обнуляется, а данные миниатюры по `JPEGInterchangeFormat`/`Length` отбрасываются, если они лежат в хвосте и их можно безопасно отрезать.

Билдер фикстур дополняется размерами SHORT и LONG, IFD1 с миниатюрой и GPS IFD.

### Acceptance criteria

- [ ] После ресайза JPEG с включённым переключателем размеры в EXIF совпадают с фактическими размерами выхода.
- [ ] Тесты для SHORT и LONG, для `II` и `MM`: в размерах записаны переданные значения.
- [ ] После патча IFD1 отсутствует, а миниатюра из хвоста обрезана.
- [ ] Остальные теги, включая дату, указатель на GPS IFD и модель камеры, сохранены байт в байт.
- [ ] Тест на выход за границы при некорректных смещениях IFD и тегов: ошибка, а не мусор.

## Phase 4: HEIC и AVIF через ISOBMFF

**User stories**: 4, 5, 6, 13

### What to build

Общий для HEIC и AVIF экстрактор ISOBMFF. Он находит item типа `Exif` через `meta`/`iinf`/`iloc`, читает данные по `iloc` и пропускает смещение до TIFF-заголовка, записанное в начале payload'а. Поле экстрактора заполняется в реестре для HEIC и AVIF. Билдер фикстур получает обёртку ISOBMFF.

### Acceptance criteria

- [ ] Тесты экстрактора на синтетическом ISOBMFF: EXIF извлекается с учётом смещения до TIFF-заголовка. Если `Exif` item отсутствует, возвращается «нет EXIF». Если структура битая, выдаётся ошибка.
- [ ] Round-trip из ISOBMFF в JPEG проходит.
- [ ] Ручная проверка реального HEIC с iPhone в JPEG с включённым переключателем: `exiftool` показывает дату съёмки, GPS и модель камеры, Orientation = 1, портретный снимок отображается вертикально и не повёрнут дважды.
- [ ] AVIF с EXIF конвертируется в JPEG с метаданными, AVIF без EXIF конвертируется как обычно.

## Phase 5: WebP и PNG, смешанный пакет

**User stories**: 11, 12, 26, 27

### What to build

Добавляются экстракторы RIFF-чанка `EXIF` для WebP и PNG-чанка `eXIf`, который может стоять в любой позиции, в том числе после `IDAT`. Поле экстрактора заполняется в реестре для WebP и PNG. Билдер фикстур получает обёртки RIFF и PNG. В конце фазы проводится ручная проверка смешанного пакета.

### Acceptance criteria

- [ ] Тесты экстрактора WebP: EXIF извлекается, при отсутствии чанка возвращается «нет EXIF».
- [ ] Тесты экстрактора PNG: `eXIf` находится и до, и после `IDAT`, при отсутствии чанка возвращается «нет EXIF».
- [ ] Round-trip из WebP и PNG в JPEG проходит.
- [ ] Ручная проверка пакета из JPEG, HEIC, PNG, WebP, AVIF, GIF, BMP, TIFF, SVG и PDF, сконвертированного в JPEG с включённым переключателем: у файлов с EXIF метаданные сохранены, остальные сконвертированы без ошибок.
- [ ] Скорость конвертации с включённым переключателем на глаз не отличается от конвертации с выключенным.
