# Plan: Упрощение типизации настроек конвертации

> Source SPEC: `spec/simplify-conversion-settings-types.md`

## Architectural decisions

Решения, общие для всех фаз:

- **Единый источник правды**: константный массив выходных форматов в порядке `jpeg, png, webp, pdf, bmp, gif, tiff`. Из него выводятся тип выходного формата, циклическое переключение и список выбора формата.
- **Производные форматы**: входной формат = выходной + `heic` + `svg`; формат с превью = входной без `tiff` и `heic`. MIME задаётся константным объектом с ключами по входному формату, тип MIME выводится из него.
- **Опции**: сглаживание (`off | low | medium | high`), дизеринг (`off` + варианты gif.js, включая serpentine), компрессия PDF (`jpeg | png`), единицы ресайза (`pixels | percentages`). Все опции задаются `as const`-массивами с выведенными union'ами.
- **Модель настроек**: настройки ресайза (флаг, единицы, ширина/высота, которые могут отсутствовать, сглаживание) и карта «формат → настройки»:
  - JPEG, WEBP: ресайз + качество;
  - PNG, BMP, TIFF: только ресайз;
  - GIF: ресайз + качество + дизеринг + склейка + задержка;
  - PDF: ресайз + качество + компрессия + склейка.
- **Выходная цель**: дискриминированный union `{ format, settings }`, выведенный из карты через mapped type. Сужается обычным `switch` по формату.
- **Форма состояния слайса настроек**: активный формат, выходные настройки (карта по формату) и входные настройки (`{ pdf: { resolution, rotation } }`).
- **Значения в сторе = значения в UI**: `off` вместо `false`. Качество 1–100 для JPEG/WEBP/PDF (по умолчанию 75) и 1–20 для GIF, где больше значит лучше (по умолчанию 10). В единицы библиотек значения переводятся только на границе: в энкодерах, агрегаторах, ресайзе и SVG-декодере.
- **Раскладка типов**: модуль форматов, модуль файлов, модуль типов рядом со слайсом настроек, модуль задачи рядом с воркером. В общем модуле типов остаются только enum'ы языка, ориентации экрана и цветового режима. Глобального `declare global` нет.
- **Персистентность**: настройки персистятся одним persist-конфигом слайса. У него `version: 1` и миграция, которая сбрасывает любое более старое состояние к начальному. Корневой persist удаляется.
- **Контроль качества**: автотестов нет. После каждой фазы должны проходить скрипт проверки типов и линтер, и каждая фаза оформляется отдельным коммитом.
- **Релиз**: фазы 4–6 меняют сохраняемые значения, а миграция срабатывает один раз при переходе на версию 1. Поэтому эти фазы выкатываются вместе, в одном релизе с фазой 4 или позже.

## Phase 1: Скрипт typecheck, форматы и MIME на константах ✅

**User stories**: 2, 4, 5, 6, 7, 51, 52

### What to build

Добавить скрипт проверки типов без генерации файлов. Создать модуль форматов:
- константный массив и тип выходных форматов;
- входные форматы и форматы с превью, выведенные из выходных;
- проверка превью-формата;
- объект MIME и выведенный из него тип MIME.

Перевести на эти типы всех потребителей enum'ов входных и выходных форматов, форматов с превью и MIME, затем удалить эти enum'ы. MIME результата конвертации и склейки брать из объекта MIME, а не собирать шаблоном. Это исправляет MIME склеенного PDF.

### Acceptance criteria

- [x] Скрипт typecheck есть в `package.json`, typecheck и lint проходят.
- [x] Enum'ов входных и выходных форматов, форматов с превью и MIME больше нет.
- [x] Нет перекрёстной индексации настроек входным enum'ом и наоборот.
- [x] MIME нигде не собирается шаблонной строкой с кастом.
- [x] Склеенный PDF имеет MIME `application/pdf`: скачивание и превью работают.
- [x] Превью открывается для тех же форматов, что и раньше.

## Phase 2: Опции селектов на константных массивах, удаление enum'а единиц ✅

**User stories**: 8, 23, 24, 25

### What to build

Заменить enum'ы сглаживания, дизеринга, компрессии PDF и единиц `as const`-массивами с выведенными union'ами. Селекты рендерят опции из этих же массивов. Единицы ресайза сужаются до `pixels | percentages`, а enum единиц удаляется целиком. Числовое поле вместо enum единиц принимает произвольную строку-подпись (px, %, ppi, °, ms).

### Acceptance criteria

- [x] typecheck и lint проходят.
- [x] Enum'ов единиц, сглаживания, дизеринга и компрессии нет.
- [x] Тип единиц ресайза не допускает `ppi`, `deg` и `ms`.
- [x] Все селекты показывают те же опции, числовые поля показывают те же подписи.

## Phase 3: Модульные типы вместо глобального объявления

**User stories**: 42, 43, 44, 45

### What to build

Убрать `declare global` целиком и разложить типы по модулям:
- **файлы** (исходный и обработанный файл) — в общий модуль файлов;
- **настройки** — в модуль рядом со слайсом настроек;
- **задача конвертации и её результат** — в модуль рядом с воркером; заодно исправляется опечатка в имени типа задачи.

Все потребители импортируют типы явно. В общем модуле типов остаются только enum'ы языка, ориентации экрана и цветового режима.

### Acceptance criteria

- [ ] typecheck и lint проходят.
- [ ] В проекте нет `declare global` для прикладных типов.
- [ ] Происхождение каждого прикладного типа видно по импорту.
- [ ] Опечатки в имени типа задачи нет.
- [ ] Поведение приложения не изменилось.

## Phase 4: Плоское состояние, карта настроек, persist v1

**User stories**: 3, 26, 27, 28, 29, 32, 46, 47, 48, 49, 50

### What to build

Перестроить слайс настроек на плоскую форму: активный формат, выходные настройки и входные настройки.
- Выходные настройки задаются картой «формат → настройки», начальное состояние проверяется на полноту через `satisfies`.
- Список форматов больше не хранится в состоянии: и циклическое переключение, и список выбора формата используют константу.
- Явный выбор формата принимает тип выходного формата.
- Редьюсеры читают draft напрямую, без снимка.

Персистентность:
- корневой persist-редьюсер удаляется, стор комбинирует слайсы напрямую;
- persist-конфиг настроек получает версию 1 и миграцию, которая сбрасывает старое состояние;
- игнорируемые экшены redux-persist в проверке сериализуемости сохраняются.

### Acceptance criteria

- [ ] typecheck и lint проходят.
- [ ] Если у одного из форматов в начальном состоянии нет настроек, компиляция падает.
- [ ] Списка форматов нет в состоянии и в localStorage, отдельного селектора списка нет.
- [ ] Кнопка переключения формата циклически проходит форматы в прежнем порядке, выбор из списка работает.
- [ ] В localStorage настройки пишутся под одним ключом.
- [ ] Старое сохранённое состояние один раз без ошибок сбрасывается к начальному, новые настройки переживают перезагрузку.

## Phase 5: `off` в сторе, перевод на границе с библиотеками

**User stories**: 9, 10, 11

### What to build

Сглаживание и дизеринг хранят «выключено» как `off`, так же, как в UI. Преобразований между стором и компонентами больше нет.
- Утилита ресайза и SVG-декодер включают сглаживание только если значение не `off`. После этой проверки значение сужается до качества сглаживания Canvas без каста.
- GIF-энкодер и GIF-агрегатор передают в gif.js `false` при `off` и само значение в остальных случаях.

### Acceptance criteria

- [ ] typecheck и lint проходят.
- [ ] В сторе нет значения `false` для сглаживания и дизеринга, в компонентах и редьюсерах нет преобразований `off ↔ false`.
- [ ] Про `false` знают только ресайз, SVG-декодер, GIF-энкодер и GIF-агрегатор.
- [ ] Ресайз со сглаживанием `off` и с каждым уровнем, а также GIF с дизерингом `off` и с вариантами работают как раньше.

## Phase 6: Качество в пользовательских шкалах

**User stories**: 12, 13, 14, 15

### What to build

Качество хранится ровно в том виде, в каком его видит пользователь:
- JPEG/WEBP/PDF: 1–100, по умолчанию 75;
- GIF: 1–20, где больше значит лучше, по умолчанию 10.

В единицы библиотек значение переводится только на границе:
- энкодеры JPEG/PNG/WEBP и PDF делят его на 100;
- GIF-энкодер и GIF-агрегатор передают в gif.js `21 − quality`.

Слайдер показывает значение как есть, границы шкалы задаёт вызывающий код. Режимы конвертации слайдера и утилита конвертации значений удаляются.

### Acceptance criteria

- [ ] typecheck и lint проходят.
- [ ] Enum'а режимов слайдера и утилиты конвертации значений нет, слайдер не знает о форматах.
- [ ] По умолчанию слайдер показывает 75 для JPEG/WEBP/PDF и 10 для GIF.
- [ ] В gif.js по умолчанию уходит 11, в энкодеры JPEG/WEBP/PDF — 0.75.
- [ ] Результат конвертации на крайних и средних значениях слайдера совпадает с прежним.

## Phase 7: Гранулярные экшены, controlled-инпуты, `switch` в панели

**User stories**: 16, 17, 18, 19, 20, 21, 22, 30, 31, 33, 35

### What to build

Заменить общие экшены с динамическими ключами набором маленьких экшенов с точным типом payload:
- **ресайз**: флаг, единицы (заодно сбрасывают ширину и высоту), ширина, высота, сглаживание;
- **формат-специфичные**: качество, дизеринг, компрессия, склейка, задержка анимации (пустое значение превращается в 200). Если у активного формата нет такого поля, экшен молча ничего не делает;
- **входные настройки PDF**: разрешение, поворот;
- **сброс активного формата**: типизирован через дженерик-хелпер по формату без кастов и по-прежнему сбрасывает входные настройки PDF.

Инпуты становятся controlled-компонентами со значением и `onChange` и не знают о сторе:
- чекбокс, селект, числовое поле, слайдер;
- селект — дженерик по union'у опций;
- у числового поля и слайдера числовые границы и шаг.

Селектор активной выходной цели отдаёт пару «формат + настройки». Панель выходных настроек выбирает формат-специфичный блок через `switch` по формату и передаёт в инпуты колбэки с dispatch. Панель входных настроек передаёт колбэки разрешения и поворота.

### Acceptance criteria

- [ ] typecheck и lint проходят.
- [ ] В редьюсерах нет извлечения первого ключа payload и кастов.
- [ ] Одноключевых типов и их объединений нет.
- [ ] Инпуты не импортируют стор и хуки dispatch.
- [ ] `onChange` селекта получает значение точного union-типа.
- [ ] В панели нет тайпгардов на наличие полей, сужение идёт через `switch` по формату.
- [ ] Каждая настройка каждого формата меняется из UI.
- [ ] Смена единиц очищает ширину и высоту, пустая задержка становится 200.
- [ ] Сброс формата восстанавливает его настройки и настройки растрирования PDF.

## Phase 8: Выходная цель в конвертере, воркере, декодерах и энкодерах

**User stories**: 34, 36, 37, 38, 39, 40, 41

### What to build

**Задача конвертации.** Один тип задачи для воркера и основного потока: MIME-тип, blob URL, выходная цель, опциональные входные настройки PDF и опциональный bitmap. Результат — blob или массив blob'ов. Оба типа используются и в пуле воркеров, и в конвертере. Воркер по-прежнему явно выбрасывает ошибку, если для PDF нет входных настроек или для SVG нет bitmap.

**Конвертер.** Конструктор принимает выходную цель, плоские входные настройки PDF (из нового селектора) и dispatch. Флаг склейки выводится внутри по полю склейки, MIME результата берётся из объекта MIME.

**Декодеры и энкодеры.**
- Декодеры, SVG-растеризатор, функция кодирования canvas и GIF-агрегатор принимают выходную цель одним аргументом; PDF-декодер дополнительно получает входные настройки PDF.
- Функция кодирования canvas сужает настройки через `switch` по формату и передаёт энкодерам уже суженные настройки.

**Слайс обработки файлов.** Место создания конвертера использует новые селекторы и форму состояния.

**Тайпгарды.** Файл тайпгардов удаляется. Проверка обработанного файла заменяется проверкой наличия ссылки на скачивание.

### Acceptance criteria

- [ ] typecheck и lint проходят.
- [ ] Задача конвертации описана один раз, у конструктора конвертера 3 аргумента.
- [ ] Формат и настройки нигде не передаются раздельно.
- [ ] Файла тайпгардов нет, в энкодерах нет тайпгардов и кастов настроек.
- [ ] Ручная проверка в dev-режиме по каждому выходному формату:
  - [ ] изменение каждой настройки;
  - [ ] конвертация одиночных и многостраничных файлов (TIFF, GIF, PDF, SVG, HEIC);
  - [ ] склейка в GIF и в PDF, у PDF корректный MIME;
  - [ ] растрирование PDF;
  - [ ] сброс настроек формата;
  - [ ] после перезагрузки настройки сохраняются, а старый localStorage один раз сбрасывается без ошибок.
